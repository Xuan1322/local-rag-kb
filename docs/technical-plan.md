## 一、使用场景

### 目标用户
需要在本地管理资料、围绕资料提问、并判断回答是否有依据的个人用户。例如：
- 把产品手册、学习笔记、行业报告放进知识空间，随时提问
- 准备面试时，把简历、项目经验、公司资料放进一个空间，模拟问答
- 学习新技术时，把官方文档、教程放进一个空间，边学边问

### 核心解决的问题
1. **资料放在哪** — 分散在不同文件夹的文档，需要一个统一入口
2. **怎么问答** — 针对自己的资料提问，不依赖通用 AI 的幻觉知识
3. **怎么判断靠不靠谱** — 回答必须带来源，能跳回原文验证

### 非目标（明确不做）
- 团队协作 / 权限管理 / 共享发布
- 工作流编排 / Agent 工具调用
- 云端部署 / 多端同步
- 支持十几种模型 / 高级参数面板

## 四、数据模型

### KnowledgeSpace（知识空间）
```
id              int       主键
name            string    空间名称
description     string    描述（可空）
created_at      datetime  创建时间
updated_at      datetime  最后使用时间
```

### Document（文档）
```
id              int       主键
space_id        int       所属空间（外键）
filename        string    原始文件名
file_path       string    存储路径（原始文件）
file_size       int       文件大小（字节）
mime_type       string    文件类型
status          string    处理状态：pending / parsing / chunking / embedding / ready / failed
error_message   text      失败时的错误信息
created_at      datetime  导入时间
updated_at      datetime  最后更新
```

### TextChunk（文本分块 + 向量）
```
id              int       主键
document_id     int       所属文档（外键）
content         text      分块原文内容
chunk_index     int       在文档中的顺序
start_offset    int       在原文中的起始字符位置
end_offset      int       在原文中的结束字符位置
metadata        json      元数据（页码、标题层级等）
```
> 向量不存 SQLite，存在 Chroma DB 中，以 chunk.id 作为关联键

### Conversation（对话）
```
id              int       主键
space_id        int       所属空间（外键）
title           string    对话标题（自动生成，取第一句话前20字）
created_at      datetime  创建时间
updated_at      datetime  最后更新时间
```

### Message（消息）
```
id              int       主键
conversation_id int       所属对话（外键）
role            string    user / assistant
content         text      消息内容
references      json      引用来源列表（仅 assistant 消息）
  └─ references: [
       { chunk_id, document_id, doc_filename, 
         snippet, score, start_offset }
     ]
created_at      datetime  创建时间
```

### 数据存储位置（全部在同一目录下）
```
data/
├── app.db              ← SQLite（元数据）
├── chroma/             ← Chroma 向量库
└── files/              ← 原始文档
    └── <space_id>/
        └── <doc_id>_<filename>
```

## 五、RAG 核心链路设计

### 5.1 文档处理流水线（导入 → 就绪）

```
用户选择文件
    │
    ▼
[1] 保存原始文件到 data/files/<space_id>/
    │
    ▼
[2] 文档解析：根据 mime_type 选择解析器
    │   PDF  → pypdf 提取文本 + 页码
    │   DOCX → python-docx 提取段落
    │   TXT/MD → 直接读取
    │
    ▼
[3] 文本切分（chunking）
    │   策略：按语义边界切分，目标 300-500 字符/块
    │   重叠：每块保留前一块末尾 50 字符（保语义连贯）
    │   约束：单个文档最多 200 块（防止内存爆炸）
    │
    ▼
[4] Embedding：调用本地 bge-small-zh-v1.5（ONNX 推理）
    │   每块文本 → 向量（512 维）
    │
    ▼
[5] 写入 Chroma DB（以 chunk.id 为关联键）
    │
    ▼
状态更新：Document.status = "ready"
```

**处理状态反馈**：每个阶段更新 `Document.status`，前端轮询或 WebSocket 推送当前进度。状态流转：
```
pending → parsing → chunking → embedding → ready
                                └─ 任何阶段失败 → failed
```

### 5.2 问答链路（提问 → 回答 + 引用）

```
用户输入问题
    │
    ▼
[1] 问题向量化
    │   Embedding(question) → query_vector
    │
    ▼
[2] 混合检索（在目标知识空间内）
    │
    │   2a. 向量检索（Chroma）
    │       cosine similarity → Top 10
    │
    │   2b. 关键词检索（SQLite LIKE + BM25 简易实现）
    │       提取关键词 → 在 chunk.content 中匹配 → Top 10
    │
    │   2c. RRF 融合（Reciprocal Rank Fusion）
    │       score = Σ 1/(k + rank)  k=60
    │       → 取 Top 5 最终结果
    │
    ▼
[3] 相似度阈值过滤
    │   如果所有结果相似度 < 0.5 → 判定为"无相关内容"
    │
    ▼
[4] 构造 Prompt
    │   System: 你是一个知识问答助手。仅根据提供的资料回答问题。
    │           如果资料中没有相关内容，明确说明"未在资料中找到相关内容"。
    │           回答末尾标注每个参考资料的 [文件名]。
    │
    │   Context: 
    │     [资料1] 来自 简历.pdf (第3页):
    │     "项目A采用了React 18 + TypeScript..."
    │     
    │     [资料2] 来自 项目经验.docx:
    │     "技术栈选型章节..."
    │
    │   User: <用户问题>
    │
    ▼
[5] 调用 LLM API（流式输出）
    │
    ▼
[6] 保存对话 + 消息 + 引用来源
    │   references 字段 = 检索到的 Top 5 chunk 信息
    │
    ▼
[7] 前端渲染
        回答文本（逐字显示） + 📎 来源卡片区域（回答完成后展示）
```

### 5.4 空状态与错误处理策略

| 场景 | 处理方式 |
|------|----------|
| **首次进入知识空间列表** | 引导文案 + "创建第一个知识空间"主按钮 + 虚线框占位 |
| **知识空间没有文档** | "这个空间还没有资料" + "导入资料"按钮 |
| **知识空间没有对话历史** | "这是一个新空间，试试问点什么" + 示例问题气泡（可点击发送） |
| **问答时未检索到相关内容** | "未在该空间的资料中找到相关内容。试试换个问法，或者导入更多资料？" （**绝对不编造答案**） |
| **文档处理失败** | 文档行显示 ⚠️ + 点击查看错误原因 + 支持重试按钮 |
| **LLM API Key 未配置** | 设置页红色提示 + 问答输入框禁用并提示"请先配置大模型" |
| **Embedding 模型未下载** | 导入文档时自动下载（显示进度条），或设置页手动触发下载 |
| **LLM API 调用失败** | 显示具体错误信息（如"API Key 无效"、"网络超时"），支持重试 |

## 七、API 设计（后端 → 前端）

### 知识空间
```
GET    /api/spaces              列出所有知识空间
POST   /api/spaces              创建知识空间 { name, description? }
GET    /api/spaces/:id          获取空间详情
PUT    /api/spaces/:id          更新空间
DELETE /api/spaces/:id          删除空间（级联删除文档/对话）
```

### 文档
```
POST   /api/spaces/:id/documents  上传文档（multipart/form-data）
GET    /api/spaces/:id/documents  列出空间下所有文档
GET    /api/documents/:id        获取文档详情（含状态）
DELETE /api/documents/:id        删除文档
POST   /api/documents/:id/retry  重新处理失败的文档
GET    /api/documents/:id/preview  获取文档纯文本内容（用于预览）
```

### 对话与消息
```
GET    /api/spaces/:id/conversations   列出空间下的对话
POST   /api/spaces/:id/conversations   创建新对话
GET    /api/conversations/:id          获取对话（含所有消息）
POST   /api/conversations/:id/chat     发送消息（流式返回）
DELETE /api/conversations/:id          删除对话
```

### 搜索测试
```
POST   /api/search/test           仅执行检索，不调用 LLM
  body: { space_id, query, top_k?, threshold? }
  response: [{ chunk_id, doc_id, filename, snippet, score, start_offset }]
```

### 设置
```
GET    /api/settings              获取当前设置
PUT    /api/settings              更新设置（部分更新）
POST   /api/settings/test-llm     测试 LLM 连接
POST   /api/settings/download-embedding  手动触发 Embedding 模型下载
```

## 九、风险与注意事项

| 风险 | 应对 |
|------|------|
| **Embedding 模型下载慢/失败** | 首次启动时自动下载，显示进度；提供手动下载按钮；失败时重试 |
| **Python 环境依赖复杂** | 提供 `requirements.txt` + 一键启动脚本（`python run.py`） |
| **Chroma 向量库并发问题** | MVP 单用户无并发，不是问题；多线程时 Chroma 有线程安全限制，用锁保护 |
| **大文件处理慢/内存爆** | 限制单文档 ≤ 20MB，单文档最多 200 块；处理中显示进度 |
| **中文检索效果不佳** | 默认用 bge-small-zh-v1.5（中文优化）；混合检索弥补纯向量缺陷 |
| **LLM API 费用** | 默认推荐 gpt-4o-mini（便宜）；用户可选其他模型；显示调用量统计 |
